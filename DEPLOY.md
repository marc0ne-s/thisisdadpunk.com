# thisisdadpunk.com

Live: **https://thisisdadpunk.com/** (custom domain, Let's Encrypt, HTTPS enforced)
Mirror: https://marc0ne-s.github.io/thisisdadpunk.com/

The DadPunk artifact site. Static HTML/CSS/JS, no build step, no framework.
Content is data-driven — edit the JSON in `assets/data/`, never the HTML.

## Deploying

This repo's `gh-pages` branch IS the deployed site (GitHub Pages, source =
`gh-pages` / root). Pushing to it publishes.

Build and push from the working copy, not by hand:

```bash
/Users/marcus/.hermes/profiles/dadpunk/scripts/deploy_site.sh github
```

That script builds a clean bundle first and refuses to push if any media
master leaked in, **or if `CNAME` is missing** (a force-push without it
unpublishes the custom domain). **Do not deploy the project directory
directly** — it holds ~965 MB of video masters and audio stems that are not
web assets. The served site is ~512 KB / 33 files.

Excluded from the bundle: `audio/`, `*.mp4`, `*.bak*`, `memory-wiki/`,
`node_modules/`, `.DS_Store`, `*.log`.

actually renders. Keep them in sync if you curate.

## Live data (system bar, footer, traces)

The bar reads `assets/data/fleet.json`; the traces panel reads
`assets/data/agent-traces.json`. Both are **generated from real machine state**,
never hand-edited:

```bash
/Users/marcus/.hermes/profiles/dadpunk/scripts/gen_fleet_json.py --dry-run  # inspect
/Users/marcus/.hermes/profiles/dadpunk/scripts/refresh_site_data.sh         # regenerate + deploy if changed
```

`refresh_site_data.sh` is wired to the Hermes cron job `dadpunk-site-data-refresh`
(every 6h, script-only, silent when nothing changed). Rules it enforces:

- **Measure or omit.** If tailscale/ssh/router can't be reached, that field is
  dropped rather than filled with a plausible number.
- **Absolute timestamps in JSON.** Every "45m ago" is computed in `artifact.js`
  from `ts`; a stored relative string freezes forever and reads as fresh.
- `active_agents` = installed Hermes profiles (not "agents currently running").
- `last_build` = newest commit across the AI repo tree; the bar shows a date
      instead of a bare HH:MM when it isn't today.

`fleet.json:disk_status` measures the APFS **Data** volume
(`/System/Volumes/Data`) plus Second-Brain-1 and SlagHeap over ssh. `df /` on
macOS reports the read-only system snapshot and understates real usage badly.

## Videos (`/videos/`)

`videos.json` is generated by `fetch_youtube.py` from the channel's public feed.
The handle lives in `~/.hermes/profiles/dadpunk/youtube-channel.txt`
(currently `@dadpunktv`), so the cron call needs no arguments.
`fetch_youtube.py @handle --remember` sets it.

```bash
python3 ~/.hermes/profiles/dadpunk/scripts/fetch_youtube.py           # regenerate videos.json
python3 ~/.hermes/profiles/dadpunk/scripts/fetch_youtube.py @handle --remember
```

Three things that will bite you:

- **Handle → channel id.** yt-dlp's flat playlist prints `NA` for `channel_id` on
  channel-tab URLs. The script scrapes the `UC…` id from the channel page and
  only falls back to yt-dlp.
- **Feed client sniffing.** YouTube's RSS endpoint returns 500 for python-urllib's
  default UA and 404 for a bare browser UA; a curl/Wget-shaped UA works. The
  script sends one and retries 3×.
- **Feed ≠ playlist.** The feed carries publish dates but no duration; the flat
  playlist carries duration but no dates. Both are fetched and merged by video id.

Feed failures are non-fatal: `videos.json` is left untouched, the hash doesn't
change, and nothing deploys. The page renders an honest "feed unreachable" state
rather than stale or invented clips.

### The player

Videos play in-page: a stage at the top of `/videos/` plus a rail of tapes, with
`?v=<videoId>` deep links so a single tape can be shared. Playback is
click-to-load — the stage shows the channel's own thumbnail until someone presses
play, so nothing from YouTube loads (and no cookies are set) on page load. The
iframe uses `youtube-nocookie.com`.

**Headless Chrome shows "Error 153 — Video player configuration error" for these
embeds. That is not a real failure.** The embed loads fine in a headed browser,
with the correct video title and thumbnail in the player chrome; the headless
error is a referrer/consent artifact. Verify embeds in a real Chrome window
(`open -a "Google Chrome" <url>` then capture), never with `--headless`.

All three current videos report `playable_in_embed: True` via
`yt-dlp --print "%(playable_in_embed)s"`, so if one ever shows "unavailable" in a
real browser, the fix is on the channel side: YouTube Studio → video details →
**Allow embedding**.

## Music (`/music/`)

One shelf, one source: **Just landed** — `assets/data/recent.json`, generated by
`fetch_recent_music.py` from Music.app's own **"Recently Added"** smart playlist
(read over AppleScript, local and read-only), collapsed to distinct albums, newest
first, with cover art exported from the library (`sips -Z 420` into
`assets/img/albums/`). The home page carries an **ON ROTATION** strip fed by the
same file.

There used to be a second shelf of shared playlists (`music.json`). It was removed
on request: a playlist that gets re-shared or re-created reads stale next to a live
library feed, and mixing the two made the page look half-updated. Don't reintroduce
playlist embeds without asking.

`assets/data/music.json` is now a **tombstone** — an empty playlist list, deliberately
still served. Nothing on the current page reads it, but Pages caches HTML for ten
minutes, so a browser holding the pre-removal `/music/` will still fetch that path.
Deleting the file turned a stale cached page into "Shelf unreachable (HTTP 404)" for
a real visitor within a minute of the deploy. When you remove a data file that
already-deployed HTML references, leave a stub behind.

```bash
python3 ~/.hermes/profiles/dadpunk/scripts/fetch_recent_music.py         # recent.json + covers
python3 ~/.hermes/profiles/dadpunk/scripts/fetch_recent_music.py --dry-run
```

Things that will bite you:

- **`?theme=dark` is not optional.** Without it Apple serves a white card that
  fights the entire page. It applies to `/album/<id>` and `/playlist/...` alike.
- **The iTunes Search API is keyless** — `itunes.apple.com/search?term=…&entity=album&country=au`.
  That is how a library album becomes a catalog id and therefore an embed. No
  developer token, no MusicKit.
- **New releases are often missing from that index.** A missing id is normal; the
  row then links to the **artist page** (`entity=musicArtist`, matched on name) and,
  failing that, says "Not on Apple Music yet". Never guess a catalog id — a player on
  the wrong album is worse than no player.
- **Never link `music.apple.com/au/search?term=…`.** It returns HTTP 200 server-side
  and then lands on an empty results page in the browser, so every one of those links
  reads as broken. Artist pages are the reliable fallback.
- **Artwork must be written from AppleScript directly to a file.** Piping the raw
  image data back through `stdout` corrupts it.
- **The cron refuses to launch Music.app.** `refresh_site_data.sh` only runs this
  when `pgrep -x Music` already finds it running, so a 6am tick can't pop the
  library open on Marcus's screen.
- Smart playlists **cannot be shared**, which is why "Recently Added" is rendered
  from local data rather than embedded as a playlist.

## Custom domain

`thisisdadpunk.com` is served by Pages with a Let's Encrypt cert and HTTPS
enforced; `www` 301s to the apex. The domain is declared by the **`CNAME` file**
on `gh-pages`, which is why `deploy_site.sh` refuses to push without it — the
deploy force-pushes, so a missing CNAME would silently unpublish the domain.

## Two things that must not regress

1. **Data fetches are relative** (`assets/data/…`, no leading slash). Absolute
   root paths work on a custom domain but break on a project-subpath host.
2. **`.nojekyll` must stay.** Without it Pages runs Jekyll and silently drops
   paths beginning with `_`.
